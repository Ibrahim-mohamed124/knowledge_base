OpenShift Virtualization: Adding a VLAN on a Bonded Interface

To expose a VLAN over a bonded interface to virtual machines in OpenShift Virtualization, you must configure the underlying nodes and expose the network to your cluster. This requires three distinct components:

  1. An Open vSwitch (OVS) bridge on the nodes.
  2. An OVN-Kubernetes bridge mapping.
  3. A NetworkAttachmentDefinition (NAD) for the virtual machines.

1. Create the OVS Bridge (NodeNetworkConfigurationPolicy)

This policy instructs Nmstate to create an L2 OVS bridge on top of your existing bonded interface across your cluster nodes.

apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: br-vm-policy
spec:
  # Leave empty to apply to all nodes, or define labels to target specific workers
  nodeSelector: {} 
  desiredState:
    interfaces:
      - name: $BRIDGE_NAME       # The name of the new bridge you are creating
        type: ovs-bridge    # Must be OVS; Linux bridges do not support OVN localnet
        mtu: "9000"
        state: up
        ipv4:
          enabled: false    # Disabled so the host does not grab an IP
        ipv6:
          enabled: false
        bridge:
          # CRITICAL: Allows OVN-Kubernetes to dynamically create internal patch ports
          allow-extra-patch-ports: true
          options:
            stp: 
              enabled: false
          ipv4:
             enabled: false 
          port:
            - name: $BOND_NAME # The physical bond interface attached to the bridge
    ovn:
      bridge-mappings:
      - localnet: $MAPPING_NAME
        bridge:  $BRIDGE_NAME
        state: present

 

2. Define the Network Attachment (NetworkAttachmentDefinition)

The NetworkAttachmentDefinition (NAD) makes the mapped network available to virtual machines in a specific namespace.

 

apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
  name: $VLAN_NAME
  # The namespace where your VMs live. VMs in other namespaces cannot see this.
  namespace: default
spec:
  config: '{
      "cniVersion": "0.4.0",
      "name": "$VLAN_NAME",         # MUST match the "localnet" name from Step 2
      "type": "ovn-k8s-cni-overlay",  # The standard CNI plugin for OVN-Kubernetes
      "netAttachDefName": "$NAMESPACE/$VLAN_NAME",
      "topology": "localnet",
      "physicalNetworkName": "$BRIDGE_MAPPINGS",  
      "vlanID": $VLAN_ID,                 # Tags egress traffic with this VLAN ID
      "ipam": {}     # Empty IPAM means VMs use static IPs or external DHCP
    }'
